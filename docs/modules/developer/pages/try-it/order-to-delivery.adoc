= Try it: an order from placing to delivery
:description: Walk one order through the whole saga with curl, and watch the events in Kafka UI.

Prerequisites: infrastructure and all services running (xref:local-run.adoc[local run]), plus
Kafka UI (`docker compose --profile tools up -d`, http://localhost:8090) to watch the topics.

== Set up

[source,bash]
----
source scripts/dev-auth.sh
GW=http://localhost:8080/api/v1
ADMIN=$(token admin); ALICE=$(token alice)
SKU=KB-$RANDOM
J='Content-Type: application/json'
uuid() { uuidgen 2>/dev/null | tr A-Z a-z || cat /proc/sys/kernel/random/uuid; }
----

== 1. Back office: a product with stock

[source,bash]
----
curl -s -X POST $GW/products -H "Authorization: Bearer $ADMIN" -H "$J" \
  -d "{\"sku\":\"$SKU\",\"name\":\"Keyboard\",\"unitPrice\":89.90,\"currency\":\"EUR\"}" | jq
curl -s -X POST $GW/stock/$SKU/receipts -H "Authorization: Bearer $ADMIN" -H "$J" \
  -d "{\"referenceId\":\"$(uuid)\",\"quantity\":10}" | jq
----

== 2. Customer: profile and order

[source,bash]
----
curl -s -X POST $GW/customers/me -H "Authorization: Bearer $ALICE" -H "$J" \
  -d '{"fullName":"Alice Example","shippingAddress":"Bağdat Cd. 1, İstanbul"}' | jq   # 409 if it exists

KEY=$(uuid)
ORDER=$(curl -s -X POST $GW/orders -H "Authorization: Bearer $ALICE" -H "$J" -H "Idempotency-Key: $KEY" \
  -d "{\"cardToken\":\"tok_ok\",\"lines\":[{\"sku\":\"$SKU\",\"quantity\":2}]}" | jq -r .id)
echo $ORDER
curl -s $GW/orders/$ORDER -H "Authorization: Bearer $ALICE" | jq '{status, paymentStatus, totalAmount}'
----

Expect `CONFIRMED` with `paymentStatus` `AUTHORIZED` within a second. In Kafka UI, `order.lifecycle`
shows `order-placed` and `order-confirmed`, `catalog.reservations` shows `stock-reserved`,
`payment.commands` shows `authorize-payment` and `payment.events` shows `payment-authorized`, all with
the order id as key. `cardToken` is the payment method; the simulated provider approves `tok_ok`.

Send the same order request again with the same `$KEY`: the answer is the same order, `200`, with
`Idempotent-Replayed: true` (add `-i` to see the headers).

== 3. Warehouse: dispatch and deliver

[source,bash]
----
SHIP=$(curl -s "$GW/shipments?orderId=$ORDER" -H "Authorization: Bearer $ADMIN" | jq -r .id)
curl -s -X POST $GW/shipments/$SHIP/dispatch -H "Authorization: Bearer $ADMIN" | jq '{status, trackingNumber}'
curl -s $GW/orders/$ORDER -H "Authorization: Bearer $ALICE" | jq '{status, paymentStatus}'   # SHIPPED, CAPTURED
curl -s $GW/stock/$SKU -H "Authorization: Bearer $ADMIN" | jq                 # onHand 8, reserved 0
curl -s -X POST $GW/shipments/$SHIP/deliver -H "Authorization: Bearer $ADMIN" | jq .status
curl -s $GW/orders/$ORDER -H "Authorization: Bearer $ALICE" | jq .status     # DELIVERED
----

== 4. Variations

* Place a second order and cancel it while `CONFIRMED`: the answer is `202`, then the order becomes
  `CANCELLED` and the stock is available again.
+
[source,bash]
----
curl -s -X POST $GW/orders/$ORDER2/cancel -H "Authorization: Bearer $ALICE" -H "$J" \
  -d '{"reason":"changed my mind"}' -w '\n%{http_code}\n'
----
* Cancel the delivered order: `409`.
* Pay with `tok_decline`: the order becomes `CANCELLED` with "Payment declined: Card declined", and
  the stock is available again.
* Read alice's order with bob's token (`$(token bob)`): `404`, as if it did not exist.
