= Web console (ff-ecommerce-ui)
:description: The React + TypeScript storefront and back-office console, how it meets the backend contract, and how its Playwright E2E suites work.

The web console lives in a companion repository, {ui-repo}[ff-ecommerce-ui], built with React 19,
TypeScript 5.8, Vite 6, TanStack Query 5, `oidc-client-ts`, Vitest and Playwright. It implements
the browser contract in xref:ui-integration.adoc[API and login for the UI] for both shoppers
(`customer`) and back-office operators (`admin`).

== Structure by bounded context

The source tree mirrors the backend's contexts so each new backend sprint plugs in as one feature
slice under `src/features/`:

[source]
----
ff-ecommerce-ui/
├── vite.config.ts          # /api -> :8080 proxy (strips Origin/Referer)
├── playwright.config.ts    # Projects: 'ui' (CI, mocked) and 'live'
├── e2e/
│   ├── fixtures/           # Mock OIDC PKCE & live Keycloak helpers
│   ├── ui/                 # Fast browser contract tests (no Docker)
│   └── live/               # Full-stack smoke suite against local stack
└── src/
    ├── app/                # Shell, navigation, routes (/callback, /admin/*)
    ├── shared/             # RFC 9457 httpClient, trace log, <dialog>, tables
    └── features/
        ├── auth/           # oidc-client-ts (in-memory), ProtocolInspector
        ├── catalog/        # Storefront + Admin catalog, prices & stock
        ├── cart/           # Cart + per-attempt Idempotency-Key
        ├── customer/       # /me onboarding + Admin customer directory
        ├── orders/         # Order detail, SagaTimeline, polling & 202 cancel
        ├── payments/       # Simulated cardToken options & paymentStatus
        └── shipping/       # Admin orders, shipments & reservations
----

== How the console honours backend guarantees

[cols="1,3"]
|===
|Guarantee |Implementation in `ff-ecommerce-ui`

|Same-origin API (no CORS)
|`vite.config.ts` proxies `/api/*` to `http://localhost:8080` (`VITE_GATEWAY_URL`) and removes
browser `Origin` and `Referer` headers on forwarded requests so the backend keeps deny-by-default
without CORS rules.

|Authorization Code + PKCE (`shop`)
|`src/features/auth/authContext.tsx` configures `oidc-client-ts` `UserManager` against
`http://localhost:8180/realms/ecommerce` with `client_id: 'shop'`, `response_type: 'code'`,
`scope: 'openid'`, `redirect_uri: '/callback'` and `post_logout_redirect_uri: '/'`. There is no
password form and no `ecommerce-dev` usage.

|In-memory tokens & no expired calls
|`userStore` uses `InMemoryWebStorage` (never `localStorage`). Before every request, `httpClient.ts`
awaits `getAccessToken()`: logged out, it sends no `Authorization` header; logged in, it refreshes
an expiring token via `signinSilent()` or clears the session rather than sending an expired token.
Single-use callback codes are deduplicated across React `StrictMode` double effects.

|Idempotent checkout & payments
|`CartProvider` stores cart items, the selected `cardToken` (`tok_ok`, `tok_decline`, `tok_slow`,
`tok_capture_fails`) and the active `Idempotency-Key` UUID in `sessionStorage` so a guest cart
survives the Keycloak redirect. Editing lines, quantities or `cardToken` rotates the key
automatically; retrying after `503 Retry-After` reuses the exact key; `200` +
`Idempotent-Replayed: true` is surfaced explicitly, and mixed currencies are blocked before submission.

|Asynchronous saga, payments & cancellation
|`OrderDetailPage` polls transitional order (`PLACED`, `CANCELLATION_REQUESTED`) and payment
(`AUTHORIZING`, `CAPTURING`, `VOIDING`) states with backoff (`500 ms` up to `3 s`) and pauses cleanly
after 30 seconds with a non-error "Still processing" banner. Slow authorizations show "Waiting for
payment"; capture failures surface an `OVERDUE` alert for operations. Cancelling a `CONFIRMED` order
opens a native `<dialog>`, surfaces `202 Accepted`, and polls until `CANCELLED` (`VOIDED`) or `SHIPPED`.

|Protocol Inspector
|A collapsible developer panel in the top bar shows decoded JWT claims (`sub`, `roles`, `aud`,
`exp`, client flow) alongside a live log of API calls with status codes, `Idempotency-Key`,
`Idempotent-Replayed`, `Retry-After`, and RFC 9457 `ProblemDetail` payloads.
|===

== Running locally

Start the backend stack first (xref:local-run.adoc[local run]). If Keycloak was started before the
`shop` client was added to `ecommerce-realm.json`, recreate it once (`docker compose up -d
--force-recreate keycloak`).

[source,bash]
----
npm install
npm run dev                  # http://localhost:5173
----

Sign in from the top bar with `alice` / `alice`, `bob` / `bob`, or `admin` / `admin`.

== Testing pyramid and CI

The UI repository separates unit tests from two Playwright browser suites:

[cols="1,2,3"]
|===
|Suite |Command |What it verifies

|Unit & component (Vitest)
|`npm run test`
|JWT decoding, `oidc-client-ts` config & StrictMode callback deduplication, RFC 9457 `httpClient`,
`Idempotency-Key` rotation, `SagaTimeline`, catalog off-sale state, native `<dialog>` accessibility.

|Browser E2E (`ui`, Playwright)
|`npm run test:e2e`
|Runs in headless Chromium with mocked `/api` and OIDC routes (no Docker needed; runs on every push
and PR in GitHub Actions). Verifies anonymous catalog headers, real `oidc-client-ts` PKCE `S256`
redirect + guest cart preservation, `503 Retry-After` & `200 Idempotent-Replayed`, `PLACED ->
CONFIRMED` polling, `202` cancellation dialog (`Escape` & submit), role boundaries, single-row admin
navigation without overflow, and Protocol Inspector.

|Live full-stack smoke (`live`, Playwright)
|`npm run test:e2e:live`
|Runs serially against the real local stack (Keycloak `:8180`, Gateway `:8080`, services, Kafka,
PostgreSQL): `admin` creates a unique SKU and books stock; anonymous guest adds it, logs in as
`alice` via Keycloak PKCE and completes `PLACED -> CONFIRMED -> DELIVERED`; `alice` tests `202`
async cancellation and `bob` verifies `404` anti-enumeration.
|===
