= Configuration reference
:description: Every setting that changes behaviour, with its default.

== Messaging (catalog, order, shipping, payment)

[cols="2,1,3"]
|===
|Property |Default |Meaning

|`ecommerce.messaging.source` |`spring.application.name` |Name written into every event envelope.
|`ecommerce.messaging.outbox.relay-enabled` |`true` |Run the background relay (tests switch it off).
|`ecommerce.messaging.outbox.poll-interval` |`500ms` |Pause between relay runs when idle.
|`ecommerce.messaging.outbox.batch-size` |`100` |Keys claimed per relay run.
|`ecommerce.messaging.outbox.max-per-key` |`50` |Messages of one key published per run.
|`ecommerce.messaging.outbox.send-timeout` |`5s` |The longest one publish attempt may take, including the wait for topic metadata: the module caps Kafka's `max.block.ms` (60 s by default) at this value, unless `spring.kafka.producer.properties.max.block.ms` is set (xref:architecture:consistency/outbox-trace.adoc[why]).
|`ecommerce.messaging.outbox.initial-backoff` |`1s` |First retry delay of a failed message; doubles.
|`ecommerce.messaging.outbox.max-backoff` |`5m` |Upper bound of the retry delay.
|`ecommerce.messaging.outbox.retention` |`7d` |How long published rows are kept.
|`ecommerce.messaging.topics.retention` |`7d` |`retention.ms` of every declared topic.
|`ecommerce.messaging.topics.dead-letter-retention` |`30d` |`retention.ms` of dead-letter topics.
|`ecommerce.messaging.inbox.retention` |`30d` |How long processed event ids are remembered. *Must be longer than the topic retention, or the service does not start.*
|`spring.kafka.admin.modify-topic-configs` |`true` (services) |Apply the declared retention to topics that already exist.
|===

== Observability (every service)

[cols="2,1,3"]
|===
|Property |Default |Meaning

|`management.tracing.sampling.probability` |`1.0` (`TRACING_SAMPLING`) |Share of requests traced. Every one in development; production would sample. The end-to-end tests set `0.0`.
|`management.opentelemetry.tracing.export.otlp.endpoint` |`http://localhost:4318/v1/traces` (`OTLP_TRACES_ENDPOINT`) |Where spans go (Jaeger's OTLP/HTTP port). Without Jaeger, spans are dropped.
|`management.otlp.metrics.export.enabled` |`false` |The OpenTelemetry starter would also push metrics over OTLP; metrics are pulled by Prometheus instead.
|`management.metrics.distribution.percentiles-histogram.http.server.requests` |`true` |Latency buckets, so p95 can be computed across instances.
|`spring.kafka.template.observation-enabled`, `spring.kafka.listener.observation-enabled` |`true` (catalog, order, shipping, payment) |Kafka records carry the `traceparent` header and consumers continue the trace.
|`management.server.port` (gateway only) |`8089` (`MANAGEMENT_PORT`) |The gateway's actuator, on a port clients never see.
|===

== Containers (compose profile `app`)

Set by {code-tree}/compose.yaml[`compose.yaml`]; nothing here is needed when the services run from
the IDE.

[cols="2,1,3"]
|===
|Variable |Value |Meaning

|`IMAGE_TAG` |`0.1.0-SNAPSHOT` |Which images to run: the local build (project version), or a commit CI published (`ghcr.io/ffetih/ff-ecommerce/<service>:<short-sha>`, or `main`).
|`KC_HOSTNAME` (Keycloak) |`http://localhost:8180` |Keycloak's fixed public address: every token's `iss`, whoever requested it.
|`KC_HOSTNAME_BACKCHANNEL_DYNAMIC` (Keycloak) |`true` |Token and key endpoints answer on the address they were called on (`keycloak:8080` inside the network).
|`ISSUER_URI` |`http://localhost:8180/realms/ecommerce` |The issuer the services check, the public one.
|`SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWKSETURI` |`http://keycloak:8080/realms/ecommerce/protocol/openid-connect/certs` |Where the services fetch the signing keys from (internal).
|`SPRING_SECURITY_OAUTH2_CLIENT_PROVIDER_KEYCLOAK_TOKENURI` (order-service) |`http://keycloak:8080/…/token` |Where order-service gets its own token (internal).
|`KAFKA_BOOTSTRAP_SERVERS`, `*_DB_URL`, `*_SERVICE_URL`, `OTLP_TRACES_ENDPOINT` |`kafka:29092`, `postgres:5432/…`, `http://<service>:<port>`, `http://jaeger:4318/…` |Service names instead of `localhost`.
|===

Each service answers `/actuator/health/readiness` (send me traffic) and `/actuator/health/liveness`
(do not restart me), open like `/actuator/health`; the container health checks use readiness.

== Payments (payment-service)

[cols="2,1,3"]
|===
|Property |Default |Meaning

|`ecommerce.payments.resolver.enabled` |`true` |Run the resolver, which asks the provider again about calls without an answer.
|`ecommerce.payments.resolver.stale-after` |`30s` |How long a provider call may stay unanswered before it is asked again, with the same idempotency key.
|`ecommerce.payments.resolver.scan-interval` |`15s` |Pause between resolver runs.
|`ecommerce.payments.resolver.batch-size` |`50` |Payments handled per run, oldest first.
|`PAYMENT_DB_URL`, `PAYMENT_DB_USER`, `PAYMENT_DB_PASSWORD` |`localhost:5432/payment_db`, `payment_service` |payment-service's own database (port 8085).
|===

The payment provider is simulated inside payment-service; the card token chooses its answer
(`tok_ok`, `tok_decline`, `tok_slow`, `tok_capture_fails`, `tok_refund_fails`). It keeps its idempotency keys in memory,
so a restart forgets them.

|===

|`CATALOG_SERVICE_URL`, `CUSTOMER_SERVICE_URL`, `ORDER_SERVICE_URL`, `SHIPPING_SERVICE_URL` |`localhost:808x` |Where each route goes. `/api/v1/returns/**` goes to order-service.
