= Security model
:description: Where tokens come from, who checks them, and what each caller may do.

Keycloak issues the tokens; every service checks them itself
(xref:adr/0008-security.adoc[ADR-0008]).

[cols="1,3"]
|===
|Concern |Rule

|Token validation
|Signature (keys from the issuer), issuer, expiry, and an audience naming the service. A service
without issuer or audience refuses to start.

|Deny by default
|Each service lists its endpoints with the roles allowed; everything else is denied. A service whose
filter chains were not built by the shared `security` module refuses to start.

|Identity
|The customer id is the token's `sub`. No request names a customer; someone else's order answers
`404`, like an unknown id.

|Service to service
|order-service calls customer and catalog with its own client-credentials token, cached, with
timeouts, renewed once when rejected.

|Gateway
|Routes only. A request that bypasses it meets the same checks.

|Operations
|Health is open for probes; `/actuator/metrics` needs the `admin` role.

|Kafka (Kubernetes)
|Every client logs in (SCRAM-SHA-512) as its own `KafkaUser` and may do only what its ACLs allow.
Compose's Kafka is open, for local development only.
|===

== Kafka permissions in the cluster

Each service's `KafkaUser` allows exactly what its code declares
(xref:adr/0013-kubernetes-gitops.adoc[ADR-0013]); nobody may create, alter or delete topics.

[cols="1,2,2,2"]
|===
|User |Write |Read |Also

|catalog-service |`catalog.stock`, `catalog.reservations` |`order.lifecycle`, `shipping.shipments` |Write on the `-dlt` of what it reads; groups `catalog-service*`
|order-service |`order.lifecycle`, `payment.commands` |`catalog.reservations`, `shipping.shipments`, `payment.events` |same
|payment-service |`payment.events` |`payment.commands` |same
|shipping-service |`shipping.shipments` |`order.lifecycle` |same
|===

A service that tries to write anywhere else is refused by the broker
(`TopicAuthorizationException`); a drill takes one ACL away and watches the alert that follows
(xref:developer:try-it/kubernetes-drills.adoc#_3_a_kafka_permission_taken_away_in_git[drill]).

Roles: `customer` (own profile and orders), `admin` (back office: catalog, stock, shipments, any
order), `service` (machine tokens). Realm and clients are described in
xref:operations:keycloak.adoc[Keycloak realm and clients].
