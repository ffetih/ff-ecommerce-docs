.Facts to build on (remove when the story is written)
====
* A PLACED order whose stock-reserved never arrives keeps its reservation; a CONFIRMED order nobody dispatches holds stock indefinitely.
* Fix: order expiry in order-service. PLACED for 30 minutes is cancelled ("Not confirmed in time"); CONFIRMED for 3 days is asked to cancel ("Not dispatched in time") through the same gate a customer uses, so expiry can never overtake a dispatch.
* CANCELLATION_REQUESTED has no timer: it waits for shipping's answer.
* Each order expires in its own transaction, locked with FOR UPDATE SKIP LOCKED, so several instances can scan at once.
* Trade-off: expiry hides the cause, so it is only safe together with the dead-letter metric.
